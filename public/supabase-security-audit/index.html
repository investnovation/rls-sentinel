What the audit adds

Four more lines in the same report

RLS Sentinel's README lists what it doesn't cover, honestly, because a security tool that overstates its reach is worse than no tool. That list is this audit's scope.

Questions people actually ask

Before you email

Do I have to give you production access?

No. A schema dump and a policy export cover most of it, and the proofs run against a branch or staging database. No customer data changes hands.

What if you find nothing?

You get a documented policy map and a clean bill of health. If I find zero issues at any severity, the audit is free.

Why not just run the free tool?

Run it first — that's what it's for, and it costs nothing. It proves row isolation and tells you honestly where it stopped. It cannot tell you your storage bucket is public, that a SECURITY DEFINER function reaches around a locked table, or that your service role key is in a client bundle.

Who is doing the work?

One person. I built RLS Sentinel and found the bug that started it in my own production app — a user id trusted from a request body instead of the verified session. The writeup is public, commit history and all.

How does it run?

Async by default, in writing. A call is optional and never the deliverable. Based in Manila, working nights — which lands on US and European business hours, so you get answers overnight rather than next week.
